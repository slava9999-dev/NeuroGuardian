ТЕХНИЧЕСКИЙ АУДИТ КОДА
NeuroAgent – AI‑агент для управления ценами на Wildberries и Ozon

🔍 ВЫЯВЛЕННЫЕ КРИТИЧЕСКИЕ ПРОБЛЕМЫ
1. Некорректный эндпоинт для обновления цен на Wildberries

* Файл: src/api-lib/services/marketplace.ts
* Функция: updateWbPrices
* Проблема: Используется эндпоинт https://discounts-prices-api.wildberries.ru/api/v2/upload/task, который, согласно документации WB на конец 2024 года, предназначен для загрузки задач на изменение цен, а не для синхронного обновления.
После успешного ответа (200 OK) задача ставится в очередь, но её выполнение может задержаться или завершиться ошибкой, о чём клиент не уведомляется.
* Риск: Пользователь видит “успех”, но цена на портале не меняется.

2. Неверный формат цены для WB

* Проблема: В функции updateWbPrices цена передаётся как number без явного указания единиц.
В документации WB указано, что цена должна быть в копейках (целое число).
Если передавать рубли, цена будет в 100 раз меньше ожидаемой.
* Пример: price: 1500 (рублей) → на WB будет интерпретировано как 15 рублей.

3. Отсутствие проверки статуса задачи WB

* Проблема: После отправки задачи в api/v2/upload/task не выполняется запрос к api/v2/upload/task/{taskId}/status для проверки, что задача успешно обработана, а не отложена или отклонена.
* Риск: “Тихая” ошибка на стороне WB (например, невалидный nmID, превышение лимитов) остаётся незамеченной.

4. Неполная обработка ошибок в updateWbPrices

* Проблема: Функция логирует ошибку, но при response.ok и наличии responseBody.error возвращает success: false только с текстом ошибки, не прерывая процесс.
При этом в handleAgentConfirm результат WB-обновления считается успешным, если response.ok, даже если responseBody.error не пуст.
* Пример кода:
javascriptDownloadCopy codeif (response.ok) {
  const responseBody = await response.json();
  if (responseBody.error) {
    console.error(...);
    return { success: false, count: 0, error: responseBody.errorText };
  }
  ...
}
В handleAgentConfirm проверяется только response.ok, а responseBody.error игнорируется.

5. Неатомарное обновление БД в handleAgentConfirm

* Проблема: После успешного ответа от WB/Ozon обновление локальной БД выполняется в цикле отдельными запросами.
Если один из запросов fail’нет, часть товаров останется со старой ценой в локальной БД, что приведёт к рассинхронизации.
* Риск: Последующая синхронизация покажет старую цену, так как локальная БД не обновилась.

6. Неверный заголовок авторизации для WB

* Проблема: В updateWbPrices используется Authorization: apiKey.
Согласно актуальной документации WB, для Prices API требуется заголовок Authorization: Bearer {apiKey} или Header: Api-Key.
Текущий формат может работать для некоторых эндпоинтов, но не для всех.

7. Ошибка в логике обновления цен Ozon

* Файл: marketplace.ts, функция updateOzonPrices
* Проблема: Используется устаревший эндпоинт v1/product/import/prices.
С 2024 года Ozon рекомендует использовать v2/product/import/prices для массового обновления.
Кроме того, в handleAgentConfirm для Ozon не извлекается product_id из item.product_id (там есть префикс ozon-), что может привести к неверному ID.

8. “Тихие” ошибки в fetchWbPrices

* Проблема: Функция fetchWbPrices ловит исключения и только логирует их, возвращая пустой Map.
Это может скрыть проблемы с сетью или API, и агент будет работать с неактуальными ценами.


🛠 ПРЕДЛОЖЕНИЯ ПО ИСПРАВЛЕНИЮ
1. Исправить эндпоинт и процесс обновления цен WB

* Рекомендуемый эндпоинт (актуальный на конец 2024):
https://discounts-prices-api.wildberries.ru/api/v2/upload/task – оставить, но добавить обязательную проверку статуса задачи.
* Добавить функцию проверки статуса:
javascriptDownloadCopy codeasync function checkWbTaskStatus(apiKey: string, taskId: string): Promise<boolean> {
  const res = await fetch(
    `https://discounts-prices-api.wildberries.ru/api/v2/upload/task/${taskId}/status`,
    { headers: { Authorization: apiKey } }
  );
  const data = await res.json();
  return data?.data?.status === 'completed';
}

* Модифицировать updateWbPrices: после получения taskId делать опрос статуса (например, 3 попытки с интервалом 5 секунд). Возвращать успех только при подтверждённом выполнении.

2. Исправить формат цены для WB

* Передавать цену в копейках (целое число).
Исправление:

Либо явно указать в документации функции, что цена должна быть в копейках.

3. Исправить заголовок авторизации WB

* Изменить на:
javascriptDownloadCopy codeheaders: {

Необходимо свериться с актуальной документацией WB Prices API.

4. Усилить обработку ошибок

* В updateWbPrices при response.ok и наличии responseBody.error считать операцию неуспешной и возвращать ошибку.
* В handleAgentConfirm проверять не только response.ok, но и responseBody.error.
* Пример:
javascriptDownloadCopy codeif (response.ok) {
  const responseBody = await response.json();
  if (responseBody.error) {
    return { success: false, count: 0, error: responseBody.errorText };
  }
  // проверить статус задачи
  const taskOk = await checkWbTaskStatus(apiKey, responseBody.data.id);
  if (!taskOk) return { success: false, count: 0, error: 'Task failed' };
  ...
}


5. Сделать атомарное обновление БД

* Обновлять цены в БД одним запросом через CASE или использовать транзакцию.

* Проверять, что nmId – число, price > 0.
* Проверять наличие префиксов (wb-, ozon-) в product_id.

8. Улучшить логирование

* Добавить структурированные логи с userId, marketplace, taskId, timestamp.
* Логировать все этапы: отправка задачи, проверка статуса, обновление БД.
