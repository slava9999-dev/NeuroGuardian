Отчет по аудиту NeuroAgent (Wildberries/Ozon API)
🔹 1. Анализ Wildberries API (WB)
✅ Выбранный endpoint актуален

* Использование https://discounts-prices-api.wildberries.ru/api/v2/upload/task корректно, поскольку документация Wb описывает именно этот эндпоинт для массового обновления цен.

🛠 Проблемы с payload:

1. 
Типы данных и формат:

nmId должен быть числом (number), что соблюдено
price в payload передается в рублях, это корректно
Но Wildberries API часто требуется передавать цены в копейках, возможно пропущена логика конвертации
Нет проверки минимальной разницы в цене (модель требует минимум 20 копеек разницы)

typescriptDownloadCopy code// Рекомендуемое изменение:
const wbPayload = {
  data: wbUpdates.map(u => ({
    nmId: u.nmId,
    price: Math.floor(u.newPrice * 100), // Конвертация в копейки
  })),
};

2. 
Тип price (рубли/копейки):

Документация WB часто требует цены в копейках
Присутствует некорректная проверка цены:

typescriptDownloadCopy code// В fetchWbPrices() есть ошибка:
if (price > 100000) {
  price = Math.round(price / 100); // КОПЕЙКИ → РУБЛИ
}

На самом деле, если WBB API вернула цену в рублях, это не нужно делить на 100
Рекомендация: всегда проверять тип и формат цены в ответе WB и использовать копейки для обновления



🛠 Логика обработки ответа:

1. 
Ответ 200 != Успех:

Проблема:WB часто возвращает 200 OK даже если обновление не прошло
Решение: Проверять responseBody.success и responseBody.data?.result?.id

typescriptDownloadCopy codeif (responseBody.error) {
  // ...
} else if (!responseBody.data?.result?.id) {
  // Ошибка выполнения задачи
} else {
  // Успех
}

2. 
Потерянные ошибки:

try-catch блок проглатывает ошибки API
Нет логирования деталей ответа
Рекомендуется добавить:

typescriptDownloadCopy codeif (!responseBody.data?.result?.id && !responseBody.data?.result?.error) {
  console.error('WB API returned OK but no result');
}



🔹 2. Анализ "тихих" ошибок
🛠 В fetchWbPrices:

* При получении ответа происходит необработанный if (price > 0) - это может привести к нулевой цене
* Нет проверки nmID в ответе
* Рекомендуется:

typescriptDownloadCopy codefor (const good of goods) {
  if (!good.nmID) {
    console.warn('WB: No nmID in good data:', good);
    continue;
  }
}

🔹 3. Анализ Ozon API
✅ Контекст:

* Используется https://api-seller.ozon.ru/v1/product/import/prices - актуальная точка для массового обновления цен

🛠 Потенциальная проблема:

* Проверка типов для product_id неочевидна
* Нет проверки на минимальные количественные требования Ozon (1-100 товаров)
* Проверить, что в теле запроса:
typescriptDownloadCopy codeconst payload = {

    }
  ]
}

🔹 5. Сквозные проблемы
Критические пункты для исправления:

1. WB цены в копейках - обязательное требование API
2. Проверка успешности -WB может вернуть 200 OK но не выполнить обновление
3. Логирование деталей ответа - необходимо для отладки
4. Обработка ошибок - не обогащено
5. Ограничение на 200 товаров в запросе - WB имеет лимит 200 элементов в одном запросе
6. Масштабирование - если пользователь обновить больше 200 товаров, нужно разбить на пакеты

Например:
typescriptDownloadCopy codefor (let i = 0; i < wbUpdates.length; i += 200) {
  const batch = wbUpdates.slice(i, i + 200);
  // ...
}
