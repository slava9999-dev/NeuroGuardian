тличная инициатива. Переход на гибридную MoE-архитектуру с локальной инференцией — это правильный шаг для масштабирования NeuroGUARDIAN. Разберу ваш RFC по пунктам и дам конкретные рекомендации.
Критический анализ текущего состояния
Проблема диагностирована верно: Синхронные вызовы Gemini при ~20 concurrent requests вызывают ECONNRESET — типичное поведение при превышении rate limits (Cloud Run/Cloud Functions на Google Cloud). Вы уплачиваете как за API-calls, так и за idle-time.
Сильные стороны подхода:

1. Локальная GPU (RTX 4070) — отличная точка входа для MoE
2. Четкое разделение интентов (price check / chat / analysis) — идеально для экспертов
3. Осознание проблемы контекста — ключевой bottleneck при 100 пользователях

Слабые места в предложении:

1. Windows + Docker для продакшн LLM может быть источником проблем
2. Отсутствие фоллбэков при сбое локальной инфраструктуры
3. State management — действительно самый сложный вопрос

D. Queue Dilemma
Рекомендация: Inngest + Redis на Fly.io/Railway
Архитектура:
Vercel (Serverless) → Inngest Cloud → Webhook → Local Worker (GPU) ← Redis на Railway

Почему именно так:

1. 
Inngest:

Нативный для Vercel (SDK)
HTTP-based — не нужно открывать порты локально

Concurrency control (важно для GPU)


2. 
Redis (Upstash или Railway):

Для кэширования контекста пользователей
Для rate limiting локальной модели
Для очередей падения (dead letter queues)

import { inngest } from "@/lib/inngest";

export const processHeavyCheck = inngest.createFunction(
  { id: "heavy-price-check" },
  { event: "price.check.requested" },
  async ({ event, step }) => {
    // 1. Проверка кэша
    const cached = await step.run("check-cache", () => redis.get(event.data.sku));
    if (cached) return cached;

    if (!localResult) {
      return await step.run("process-cloud", () => callGemini(event.data));
    }
    
    return localResult;
  }
);

Оценка критериев успеха
1. Zero ECONNRESET при 100 пользователях

* Достижимо: Inngest дедуплицирует запросы, GPU очередь регулирует нагрузку
* Потенциальная проблема: memory leaks в vector store. Решение — TTL кэшей

2. 60% cost reduction

* Реалистично: Phi-3-mini vs Gemini Pro экономит ~$0.0015 на запрос
* С 10K запросов/день → экономия $15/день → $450/месяц
* Роутер должен направлять 60% трафика на локальное исполнение

3. <2s latency для простых интентов

* Достижимо: Локальная инференция (50-200ms) + кэш Redis (10ms)
* Критично: Кэширование результатов price check на 1-5 минут
