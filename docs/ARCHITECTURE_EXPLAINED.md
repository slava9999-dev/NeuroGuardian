## 🎯 ГЛАВНАЯ ИДЕЯ

У тебя есть **ДВА типа автоматизации**:

### 1. 🤖 АГЕНТ (Интерактивный) — "Мозги"

```
Пользователь пишет → Groq (LLM) думает → Вызывает инструменты → Отвечает
```

### 2. ⚡ SENTINEL (Автономный) — "Робот-охранник"

```
Cron каждый час → Проверяет цены → Если проблема → Telegram уведомление
```

**Это РАЗНЫЕ вещи!** Агент нужен для диалога, Sentinel работает сам.

**Что нужно для Агента:**

**Что НЕ нужно:**

- ❌ Local LLM (GPU) — Groq справляется отлично
- ❌ Inngest — Нет очередей, всё синхронно

## ⚡ КАК РАБОТАЕТ SENTINEL (Автономный мониторинг)

```
┌──────────────────────────────────────────────────────────────────┐
│                    VERCEL CRON                                    │
│            Каждый день в 09:00 (или hourly с Pro)                │
│                 /api?action=check-prices                          │
└───────────────────────────┬──────────────────────────────────────┘
                            │
                            ▼
┌──────────────────────────────────────────────────────────────────┐
│                    SENTINEL SERVICE                               │
│                 (sentinel-service.ts)                             │
│                                                                   │
│  FOR EACH USER:                                                  │
│  1. Получить все товары из БД                                    │
│  2. Получить текущие цены с WB/Ozon API                          │
│  3. Сравнить: была 1000₽, стала 900₽ → ПРОБЛЕМА!                 │
│  4. Проверить price_rules: min_price = 950₽ → НАРУШЕНИЕ!         │
│                                                                   │
│  THREAT DETECTOR:                                                │
│  - Эрозия маржи (цена упала > 5%)                                │
│  - Нарушение stop-loss (цена < min_price)                        │
│  - Конкурент снизил цену                                         │
└───────────────────────────┬──────────────────────────────────────┘
                            │ Если найдены угрозы
                            ▼
┌──────────────────────────────────────────────────────────────────┐
│                    TELEGRAM NOTIFICATION                          │
│                 (notifications.ts)                                │
│                                                                   │
│  🛡️ SENTINEL — Автоматический мониторинг                         │
│  ⚠️ Обнаружена эрозия маржи!                                     │
│                                                                   │
│  Товар: Футболка (SKU: 12345678)                                 │
│  Было: 1000₽ → Стало: 900₽ (-10%)                                │
│                                                                   │
│  [✅ Вернуть 1000₽] [❌ Игнорировать]                            │
└──────────────────────────────────────────────────────────────────┘
```

**Что нужно для Sentinel:**

- ✅ Vercel Cron — запуск по расписанию
- ✅ WB/Ozon API — получение цен
- ✅ PostgreSQL — правила защиты (price_rules)
- ✅ Telegram Bot — отправка уведомлений

**Что НЕ нужно:**

- ❌ Groq/LLM — Sentinel не думает, он просто сравнивает числа
- ❌ n8n — Vercel Cron делает то же самое
- ❌ GPU — Нет AI в Sentinel

**Агент МОЖЕТ вызвать Sentinel:**

```

```

**Но Sentinel работает и БЕЗ агента:**

```
Cron в 09:00 → Sentinel проверяет ВСЕХ пользователей
```

## 🤔 ЗАЧЕМ БЫЛИ n8n, GPU, Inngest?

### n8n — Визуальный конструктор workflows

**Идея:** Вместо Vercel Cron использовать n8n
**Реальность:** n8n дублирует то, что уже есть:

| Функция               | n8n                | Уже есть               |
| --------------------- | ------------------ | ---------------------- |
| Запуск по расписанию  | Schedule node      | Vercel Cron            |
| Проверка цен          | HTTP Request → API | check-prices endpoint  |
| Отправка уведомлений  | Telegram node      | notificationService    |
| Синхронизация товаров | HTTP Request → API | sync-products endpoint |

**Вывод:** n8n не нужен, всё это делает Vercel + Telegram

---

### GPU / Local LLM — Локальная языковая модель

**Идея:** Вместо платного OpenAI использовать свою LLM
**Реальность:**

- Groq БЕСПЛАТНЫЙ (30 requests/min)
- llama-3.3-70b-versatile — мощнее любой локальной модели
- Не нужен сервер с GPU

**Вывод:** GPU не нужен, Groq бесплатно и лучше

---

### Inngest — Serverless очереди

**Идея:** Длинные задачи выполнять асинхронно
**Реальность:**

- Vercel Functions работают до 60 секунд
- Sentinel обрабатывает 100 товаров за 5-10 секунд
- Для 1000 пользователей — хватит

**Вывод:** Inngest нужен только при 10,000+ пользователей
