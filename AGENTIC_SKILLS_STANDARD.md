# 🧠 AGENTIC SKILLS ARCHITECTURE: GLOBAL STANDARD

# Version: 1.0.0 | Type: Architecture Specification & Implementation Guide

> **НАЗНАЧЕНИЕ ДОКУМЕНТА:**
> Этот документ является эталонным Техническим Заданием (ТЗ) и Руководством для внедрения системы **Агентских Скиллов (Agentic Skills)** в любой программный проект.
> Он предназначен для Агентов-Разработчиков (AI) и инженеров, чтобы стандартизировать подход к расширению интеллектуальных возможностей системы.

---

## 1. 🏗️ КОНЦЕПЦИЯ (PHILOSOPHY)

**Традиционный подход (Hard-Coded):**
Жесткая логика в коде (`if/else`, классы). Чтобы добавить новую возможность, нужно менять ядро приложения.

**Агентский подход (Skills-Based):**
Система состоит из "Ядра" (Core) и "Навыков" (Skills). Ядро — это мозг. Навыки — это подключаемые модули знаний и инструментов.
Нейросеть (Агент) сама решает, какой Скилл применить, основываясь на контексте задачи.

### Структура Скилла (The Anatomy of a Skill)

Каждый Скилл — это автономная папка в директории `.agent/skills/`.

```text
.agent/
└── skills/
    └── [skill-name]/            # Имя скилла (напр. video-production, brandbook-gen)
        ├── skill.md             # 🧠 МОЗГ: Инструкции, триггеры, правила мышления
        ├── resources/           # 📚 ПАМЯТЬ: Шаблоны, примеры, статические данные
        └── scripts/             # 🦾 РУКИ: Исполняемый код (Python/Node.js) для действий
```

## 2. 📋 ТЕХНИЧЕСКОЕ ЗАДАНИЕ НА ВНЕДРЕНИЕ (IMPLEMENTATION SPEC)

### 2.1. Подготовка Инфраструктуры

**Задача:** Создать фундаментальную структуру каталогов в корне проекта.

1.  Создать каталог `.agent` в корне проекта (если нет).
2.  Создать подкаталог `.agent/skills`.
3.  Настроить `.gitignore` (исключить временные файлы внутри скиллов, но оставить структуру).

### 2.2. Стандарт Файла `skill.md`

Это главный файл, который читает Агент. Он должен содержать YAML Frontmatter и Markdown-инструкции.

**Шаблон:**

```markdown
---
name: [Название Скилла]
description: [Краткое описание для Агента-Оркестратора]
triggers:
  - "Когда пользователь просит..."
  - "Если обнаружен файл типа..."
---

# 🧠 [Skill Name] Instructions

## 🎯 Цель (Objective)

Четко описать, какую полезную работу выполняет этот скилл.

## 🛠️ Инструментарий (Tools & Scripts)

Перечень скриптов из папки `scripts/`, которые Агент имеет право запускать через `run_command`.
Пример:

- `script_one.ts`: Делает А. Запуск: `npx tsx .agent/skills/[skill]/scripts/script_one.ts <arg>`

## 📋 Протокол Действий (Workflow)

Пошаговый алгоритм, как Агент должен "думать" и действовать.

1. Проанализируй входные данные.
2. Если X, запусти скрипт Y.
3. Проверь результат.
4. Сформируй ответ пользователю.

## ⚠️ Ограничения (Constraints)

Что делать ЗАПРЕЩЕНО (например, удалять файлы без спроса).
```

### 2.3. Интеграция с Кодом (Scripts)

Скрипты внутри скилла должны быть **атомарными** и **самодостаточными**.

- Язык: TypeScript (через `tsx`) или Python.
- Вход: Аргументы командной строки (`process.argv`).
- Выход: `stdout` (JSON или текст) или файлы в файловой системе.
- Зависимости: Должны использовать `package.json` основного проекта или иметь свой локальный (если сложная изоляция).

## 3. 🚀 ПРИМЕРЫ ВНЕДРЕНИЯ (USE CASES)

### Кейс А: "Генератор Брендбука" (из видео)

- **Задача:** По ссылке на сайт создать PDF с цветами и шрифтами.
- **Skill:** `.agent/skills/brandbook-generator`
- **Script:** `extract_styles.ts` (использует Playwright для парсинга CSS).
- **Logic:** Агент понимает интент "сделай брендбук" -> вызывает скилл -> скилл запускает скрипт и отдает PDF.

### Кейс Б: "Умный Кодер" (Dev Tools)

- **Задача:** Сгенерировать React-компонент по скриншоту.
- **Skill:** `.agent/skills/ui-wizard`
- **Resource:** `best-practices.md` (правила чистого кода, Tailwind классы).
- **Logic:** Агент читает `best-practices.md` перед написанием кода, чтобы результат был идеальным.

## 4. ИНСТРУКЦИЯ ДЛЯ АГЕНТА-ИСПОЛНИТЕЛЯ

**Ты — Агент, получивший это ТЗ. Твои действия:**

1.  **Просканируй** текущий проект. Определи, где уместно внедрить `.agent/skills`.
2.  **Создай** структуру папок и базовый шаблон.
3.  **Перенеси** сложные, неочевидные скрипты из корня/src в соответствующие Скиллы, описав их логику в `skill.md`.
4.  **Обучи** систему (через системный промпт или контекст), что теперь она должна искать инструкции в `.agent/skills/`.

> **CRITICAL:** Скиллы делают систему гибкой. Не пиши жесткий код там, где можно создать Скилл. Код — это молоток. Скилл — это мастер, знающий, куда ударить.
